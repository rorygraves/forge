## Outcome — ✅ the committed-vs-local split landed exactly as the contract requires

The instance was created and `szork` registered with the live CLI
(`init-instance` / `add-repo` / `list-repos` — Tasks 4.0.2/4.0.3 validated
end-to-end), then a feature was driven under `--instance llm4s` through the
design phase and abandoned. The B1 split on disk:

| Family | Location | Files |
|---|---|---|
| **local-runtime** (re-rooted) | `~/.forge/instances/llm4s/workers/<feat>/.forge/` | `log/<feat>.jsonl`, `state/<feat>.json`, `state/.lock` |
| **committed** (stays in repo) | `szork/.forge/specs/<feat>/` | `design.md`, `decomposition.md`, `manifest.json`, `pieces/p1.md` |

Negative check: **no** `<feat>.jsonl` under `szork/.forge/log/` and **no**
`<feat>.json` under `szork/.forge/state/` — the local-runtime family did not leak
into the checkout. The re-root is driven only by the explicit `--instance` flag;
each state-changing command printed the one-line stderr note locating the
re-rooted runtime.

```
forge init-instance llm4s
forge add-repo --instance llm4s <szork>   →  list-repos shows the registered path
forge new  <feat> --instance llm4s        →  design branch + seed manifest in repo; lock under instance dir
```

## Run shape and scope

Per the operator decision, this was a **minimal re-root proof, then abandon** —
driven through the design phase (enough to write the full local-runtime + spec
families and exercise the orchestrator under re-rooted paths), not all the way to
`FeatureDone`. The exit criterion is the *disk split under a live run*, which is
fully visible at `DesignReviewing`; the FSM/CI/merge machinery behind the B1 seam
is frozen and already proven by dogfoods #1–#4. The run stopped before
`DesignAwaitingMerge`, so **no design PR or remote branch was created on
`llm4s/szork`** — zero outward footprint. The original `extract-media-network-config`
refactor had already merged to `main`, so the spec driver (correctly) noted the
implementation already exists and specced to match the tree; the feature content
is incidental to the re-root proof. The re-run used a `-reroot` suffix so it did
not collide with the already-committed `extract-media-network-config` specs.

## Notes / friction

- **B1 incidentally fixes dogfood #2's finding #2.** That run's `forge new`
  preflight failed its own clean-worktree check because lock acquisition wrote
  `.forge/state/.lock` into the checkout before preflight ran. Under the instance
  re-root the lock lands in `~/.forge/instances/<name>/workers/<feat>/.forge/`,
  not the checkout, so it can never dirty the worktree — the friction is gone for
  the instance path. (The v1 no-instance path is unchanged; szork also keeps
  `.forge/` git-ignored, which masks it there too.)
- **`--instance` placement.** The flag is part of the *command's* argument list
  (`forge <cmd> … --instance <name>`), not a global option — it must come after
  the command name (a leading `--instance` is rejected as an unknown command).
