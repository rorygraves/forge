# Dogfood run #6 — `daemon-smoke` — Slice 4.1 daemon crash-recovery live proof

> Sixth real Forge exercise (2026-06-06), driven to close
> [`../design-4.1.md`](../design-4.1.md) **Task 4.1.5** — the live demonstration
> of the Phase-4 **§6.4 / O8 durability contract**: a daemon supervisor that
> survives a **hard crash** (SIGKILL, no clean stop) and rebuilds its *entire*
> view — boot count, worker record, latest status, and the exported per-feature
> event tail — from the **instance log alone** when even the derived state cache
> is gone.
>
> Unlike the feature-driving dogfood runs (#1–#5), this exercises the daemon
> transport, not a connector: a real `forge daemon start` OS process plus an
> **external** JSON-RPC client (a 10-line Python Unix-socket script) standing in
> for the worker that 4.2 will spawn. Evidence captured under
> [`4.1-daemon/`](4.1-daemon/): `instance-log.jsonl` (the canonical log after
> restart) and `state-cache.json` (the cache the restart rebuilt).

## Outcome — ✅ the §6.4 log-is-canonical recovery landed exactly as the contract requires

The throwaway `daemon-smoke` instance was created under the real `~/.forge`, a
daemon started as a genuine background OS process (pid 342), a worker registered
and driven over its Unix socket by an external client, then the daemon was
**`kill -9`'d** and its state cache deleted. A fresh `forge daemon start` (pid
1858) rebuilt the identical view from the log alone.

| Step | Command / client | Observed |
|---|---|---|
| create | `forge init-instance daemon-smoke` | instance at `~/.forge/instances/daemon-smoke` |
| start (boot #1) | `forge daemon start --instance daemon-smoke` (bg OS proc, pid 342) | `listening on …/daemon.sock (boot #1)` |
| register + drive | external Python client over `daemon.sock` | `register-worker` w1 → `worker-status` Refining → `worker-event` alpha, beta — all acked |
| status (pre-crash) | `forge daemon status --instance daemon-smoke` | `running (boot #1, 1 worker(s)) — w1 feature=live-feature status=Refining events=2` |
| **hard crash** | `kill -9 342` | no clean `shutdown` RPC; no final state flush |
| drop cache | `rm state/instance.json` | only the canonical log survives on disk |
| restart (boot #2) | `forge daemon start --instance daemon-smoke` (pid 1858) | reclaims the stale lock; `listening … (boot #2)` |
| status (post-restart) | `forge daemon status` | **`running (boot #2, 1 worker(s)) — w1 feature=live-feature status=Refining events=2`** |
| subscribe | external client `subscribe` | streamed the rebuilt tail: `worker.registered` → `worker.status` → `worker.event{alpha}` → `worker.event{beta}` |
| stop | `forge daemon stop --instance daemon-smoke` | clean shutdown ack |

The canonical log after restart (`instance-log.jsonl`) — note `daemon.started`
at `seq 5` is the **second** boot appended on restart, after the worker records
that survived the SIGKILL:

```
seq 0  daemon.started   {pid: 342}      ← boot #1
seq 1  worker.registered {w1, /repo, live-feature}
seq 2  worker.status     {w1, Refining}
seq 3  worker.event      {w1, {tag: alpha}}
seq 4  worker.event      {w1, {tag: beta}}
seq 5  daemon.started   {pid: 1858}     ← boot #2 (restart after kill -9)
```

The cache the restart rebuilt (`state-cache.json`) carries `bootCount: 2` and the
full worker record including both exported events — proving the rebuild
reconstructed *content*, not just counts, from the log.

## Why a hard crash, not a clean stop

The clean `forge daemon stop` path (a `shutdown` RPC + the 250 ms ack-flush
grace) was deliberately *not* used to reach boot #2 — that path gets to flush. A
`kill -9` skips every finalizer: no socket-file cleanup, no cache write, no
ordered teardown. The only thing the recovery can rely on is what each
single-writer `DaemonState.record` already committed durably to the log
(`CREATE|APPEND|SYNC`) at the moment of each append. Deleting the cache before
restart removes the last fortunate shortcut, so the rebuild is provably
log-driven (§6.4 invariant: the log is canonical, the cache is a derivable
convenience).

## Relationship to the automated proof

`DaemonCrashRecoverySuite` (forge-daemon) is the in-process automated version of
this exercise: it boots a daemon, registers a worker and pushes events over the
socket, cancels the serve fiber abruptly (no `shutdown` signal), deletes the
cache, reboots, and asserts the `status` snapshot + the `subscribe`d event tail
rebuild from the log. This dogfood run is the matching real-OS-process,
real-SIGKILL, real-external-client demonstration.

## Teardown

The `daemon-smoke` instance was removed from `~/.forge` after the run; only the
pre-existing `llm4s` instance remains. The Python client was a throwaway
`/tmp/rpc.py` (Unix-socket newline-delimited JSON-RPC), not a committed
artifact — the real worker process is 4.2.
