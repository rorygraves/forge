## Host platform — macOS or Linux (TCP control channel)

The containerised worker reaches the daemon over **TCP** at
`host.docker.internal:<port>` (the daemon binds an ephemeral port, writes it to
`instances/<name>/daemon.port`, and `ContainerRuntime` passes the worker
`--socket host.docker.internal:<port>` with `--add-host host.docker.internal:host-gateway`).
This crosses the Docker Desktop **macOS** VM boundary cleanly, so **this dogfood
runs on macOS** (or Linux). The earlier Unix-socket bind-mount approach failed on
macOS with `Errno 95`; the TCP migration (landed in 4.3, see
[`../design-rationale.md`](../design-rationale.md) **PH4-3**) is what makes the
container topology portable. The host-process topology (`forge daemon start`, no
`--container`) uses the same TCP transport over loopback.

## Prerequisites

1. **A Docker daemon** (`docker version` works — Docker Desktop for macOS, or a
   native Linux Docker daemon).
2. **The default worker image built:**
   ```bash
   scripts/build-forge-worker-image.sh        # sbt forge-app/assembly + docker build -> forge-worker:latest
   ```
   (Or commit a `Forgefile` in the target repo pinning a custom image — O1.)
3. **The `forge` launcher installed** on the host (`scripts/install-forge.sh`), or
   run via `sbt forge-app/run …`.
4. **Brokered credentials configured as host env vars** (O6 — these are read by
   `RealCredentialBroker` and vended over the TCP control channel; they are
   **never** mounted or put in the container spec):
   - `FORGE_GH_TOKEN` — a **per-repo scoped** `gh` token (a fine-grained PAT scoped
     to the dogfood repo, *not* your host-wide `gh auth` login). Required — the
     broker **refuses** rather than falling back to a host login.
   - `ANTHROPIC_API_KEY` and/or `OPENAI_API_KEY` — agent auth for `claude`/`codex`.
5. **A target repo registered in the instance with a designed feature** (a clone
   that has a `.forge/specs/<feature>` manifest, so the worker has something to
   drive — e.g. a small `szork` feature, as in dogfood #7).

## O6 credential-isolation verification (the G4 safety claim)

While the worker container is running (step 7), capture and assert:

```bash
docker inspect forge-ctr-smoke-w-1 \
  --format 'MOUNTS:{{range .Mounts}}{{.Source}}->{{.Destination}} {{end}}{{"\n"}}HOSTS:{{.HostConfig.ExtraHosts}}{{"\n"}}ENV:{{.Config.Env}}'
```

Assert:

- **No host home mount, no socket mount.** The `Mounts` are **exactly one** — the
  isolated clone *worker root* (`…/instances/ctr-smoke/workers/w-1` →
  `/forge/worker`). **No `$HOME` / `~/.forge` / `~/.claude` / `~/.config/gh` mount,
  and no daemon-socket mount, appears** (the daemon is reached over TCP, not a
  mount). `HostConfig.ExtraHosts` carries `host.docker.internal:host-gateway`.
- **No secrets in the container spec.** `Config.Env` carries **no** `GH_TOKEN` /
  `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` — the spec is `docker inspect`-safe. The
  worker obtained them over the TCP control channel (`broker-credentials`) and set
  them in its **own** process env only.
- **The `gh` token is scoped.** The token the worker uses is the per-repo
  `FORGE_GH_TOKEN`, not your host-wide login (verify the PR/push it makes is
  attributed to the scoped token's identity / fine-grained scope).

Save the `docker inspect` output to `4.3-container/inspect-w-1.txt`.

## Expected instance-log shape (illustrative)

```
seq 0  daemon.started     {pid: …}                              ← boot #1 (container mode)
seq 1  workstream.created  {ws-1, goal …}
seq 2  worker.spawned      {w-1, ws-1, …/repo, <feat>, checkout …, containerId: <id>}   ← a container id, NOT a pid
seq 3  workstream.status   {ws-1, Active}
seq 4  worker.registered   {w-1, …/repo, <feat>}               ← reached the daemon over TCP (host.docker.internal:<port>)
seq 5  worker.event        {w-1, fsm.transition …}
seq 6  budget.reserve      {w-1, ws-1, estimateUsd: <cap>}     ← before the first driver spawn
seq 7  budget.grant        {w-1, ws-1, reservationId …, estimateUsd: <cap>}
seq 8  worker.event        {w-1, driver.spawn …}
seq 9  worker.event        {w-1, cost.update {usd: <actual>}}  ← the real spend
seq 10 budget.finalize     {w-1, reservationId …, actualUsd: <actual>}   ← implicit on the cost.update
…
```

`worker.spawned` carrying a **`containerId`** (and **no** `pid`) is the topology
key (§6.4): this is a containerised worker, reconciled by container id across a
daemon restart. The `budget.*` quartet + the `cost.update`→`finalize` fan-in is the
B2 cycle.

## Relationship to the automated proof

`WorkerDaemonHandshakeSuite` (forge-app, always-on) is the in-process automated
version of the **logical** flow: a real `WorkerReporter` + `ReportingBudgetReserver`
walk `WorkerLoop`'s exact order (register → broker host-isolated creds → reserve →
grant → `cost.update`→finalize; plus a refuse → hold) over one real served daemon.
`ContainerRuntimeSuite` proves the **spec** (one mount, no host home, no daemon-socket
mount, no secret env, the `--add-host` + `--socket host.docker.internal:<port>` +
`forge worker … --container` argv). `SupervisorContainerReconcileSuite`'s opt-in
`FORGE_IT_RUN_DOCKER=1` test proves the **real-container reconcile-by-id** across a
daemon crash (a busybox stand-in). This dogfood is the matching real-
`forge daemon --container` / real-`forge-worker:latest` / real-`gh`+agent-CLI
demonstration that ties all three together over the **TCP** control channel — the
real container→host connect-back that the unit/opt-in suites do not exercise.
